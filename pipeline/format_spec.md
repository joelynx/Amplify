# Format spec: what the Amplify app accepts

Evidence gathered on 2026-10-18 from the app source and the database. The
condensed version the models see is `prompts/format_rules.md`; the scripts
(`validate.py`, `assemble.py`) enforce the mechanical parts.

> **v5 (2026-10-19):** the pipeline now runs on the Message Batches API with one solver call per question (see `README.md`). Rigor notes and the hint come from the solver reply, there is no reviewer, the old solution is never sent to a model, and questions that reference images are skipped instead of processed. Everything below about the accepted LaTeX subset, escaping, and field formats still applies.

## 1. Database field mapping (needs owner confirmation)

Database: `app/data/appdata/amplify.db`, table `questions` (SQLite, plain TEXT columns, no escaping).

| Pipeline concept | Column | Notes |
|---|---|---|
| unique question ID | `question_id` (INTEGER PK) | used for folder names under `outputs/` |
| question text | `latexcode` | raw LaTeX, placed verbatim in the PDF and the web view |
| old solution | `solution` | 1,221 of the 12,118 target questions have none; reviewer then sees "None", triage assigns INSIGHT |
| Answer | `answer` | 11,159 target rows empty; `N/A` placeholders (IITD, IITD-AD) are treated as empty via `empty_answer_sentinels` |
| Hint | `hints` | 11,632 target rows empty |
| images | `\includegraphics{name}` inside `latexcode` | files live in `app/data/appdata/teximages/` as the bare name or name + `.jpg/.png/.jpeg`; 180 target questions reference images |

Target set: the 36 sources listed in `config.json` (12,118 questions). Note the
spec assumed ~1,000.

Where the pipeline writes (never into existing content):

- `pipeline/pipeline.db`: `status`, `reviews`, `finals` (assembled solutions), `provenance` (every Answer/Hint fill with prompt version and date), `batches`, `events`.
- `pipeline/outputs/<question_id>/`: all solver, review, hint, final files and `preview.pdf`.
- `questions.answer` / `questions.hints` in the app database: only empty cells, applied by `apply_fields.py` (`config.app_db_writes` is true since the owner confirmed the mapping on 2026-10-18).
- `questions.generated_solution` (new column, app migration `005_generated_solution.sql`): the assembled solution, ending with the attribution line `\textit{[Generated by <model> at <effort> effort]}` (owner decision). The pipeline owns this column and may replace it on a rerun. `questions.solution` is never modified. The app's UI does not read the new column yet.

## 2. PDF pipeline (primary)

- Code: `app/tex/pdfgen.py` (assembly and runner), `app/tex/preamble.py` (fixed preamble), `app/tex/solutions.py` (placement).
- Engine: XeLaTeX, `-interaction=nonstopmode -halt-on-error`. The app prefers a bundled TinyTeX under `app/resources/tinytex/` and falls back to `xelatex` on PATH; on this machine that is MiKTeX 25.4 (no TinyTeX bundle is present). The app also strips non-directory entries from PATH before calling XeLaTeX because MiKTeX aborts otherwise; `check_pdf.py` does the same.
- Preamble: `article`; `amsmath` (+`\allowdisplaybreaks`), `amsfonts`, `amssymb`, `caption`, `graphicx` (+`\graphicspath` to teximages), `fancyhdr`, `geometry` (a4, 170x257 mm), `enumitem`, `circuitikz`, `chemfig`, `pgfplots`, `mathtools`, `stmaryrd`, `ulem`, `amsthm` with `theorem`, `lemma`, `proposition`, `corollary`, `definition`, `example`, `remark`, `note`, `claim` and their starred forms; `\parskip` 1em; `\everymath{\displaystyle}` at the start of the body (inline fractions render display-size).
- Placement of a solution: `\noindent\textbf{Q<n>.}~<solution>` either directly after its question (interleaved) or under `\section*{Solutions}` on a new page (appendix). Answers and hints are not placed in PDFs today.
- Template copy: `templates/app_template.tex`, generated by `scripts/make_template.py` from the app's preamble, with `<<IMAGE_PATH>>` and `<<CONTENT>>` slots. Regenerate it if `app/tex/preamble.py` changes.

## 3. Web view pipeline (secondary)

- Code: `frontend/src/components/browser/LatexContent.tsx` (`renderLatex`), used by the Browser side panel, the quiz question viewer, and quiz review for question, solution, answer, and hint text.
- Renderer: a custom preprocessor plus KaTeX 0.17.0 with `throwOnError: false`, `strict: "ignore"`, `output: "html"`. A KaTeX error never throws; it renders the expression in red (`katex-error`). `check_web.mjs` bundles this exact module with esbuild and fails on any `katex-error`, on raw LaTeX left in prose, and on stray braces.
- Supported outside math: `$...$`, `$$...$$`, `\(...\)`, `\[...\]`; top-level `align`, `align*`, `equation`, `equation*`, `gather`, `gather*`, `multline`, `multline*` (wrapped as display math); theorem-like text environments `proof`, `theorem`, `lemma`, `definition`, `example`, `remark`, `corollary`, `claim`, `exercise`, `solution`, `proposition`, `quote` (rendered as a labeled block); `itemize` and `enumerate` (optional argument allowed) with `\item`; `\textbf`, `\textit`, `\emph`, `\underline`, `\texttt`; `\includegraphics` (resolved through IPC); the spacing commands `\hfill \noindent \newline \linebreak \smallskip \medskip \bigskip \vfill \par` are silently removed. Newlines become `<br/>`.
- Everything else in text mode is shown literally: `\section*{...}`, `\paragraph{...}`, `\\`, `\%`, `\&`, `~`, `%` comments, `\label`, `\vspace`, `\centering`, `tabular`, `center`, `figure`, `tikzpicture`, etc.
- Inside math: whatever KaTeX 0.17 supports. Unsupported commands (`\label`, `\degree`, `\SI`, `\mathbbm`, ...) produce a red error span.

## 4. The allowed subset (works in both pipelines)

Exactly what `prompts/format_rules.md` says. In short:

- Math: `\( ... \)` inline, `\[ ... \]` display. Multi-line: `\[ \begin{aligned} ... \end{aligned} \]` or a top-level `align*`. `$` delimiters are rejected for consistency even though both pipelines accept them.
- Environments: `aligned`, `align*`, `gathered`, `gather*`, `cases`, `pmatrix`, `bmatrix`, `vmatrix`, `Vmatrix`, `Bmatrix`, `matrix`, `smallmatrix`, `array`, `split`, `subarray`, `itemize`, `enumerate`, `proof`, `claim`, `lemma`. Nothing else.
- Text structure: blank lines between paragraphs; `\textbf{...}` run-in labels; `\textit`, `\emph`. No sectioning commands, no `\\` in text, no spacing commands (the scripts add the section titles).
- Macros: the standard amsmath/amssymb set listed in the rules (all verified against the KaTeX support table and the loaded packages).
- ASCII only; no `%` anywhere except marker lines; no unescaped `& # _ ^ ~ $ { }` in text.
- Known unsafe (rejected by `validate.py`): `tabular`, `table`, `figure`, `center`, `minipage`, `tikzpicture`, `lstlisting`, `verbatim`, `theorem`, `equation`; `\section`/`\paragraph`; `\\` in text; `\label`/`\ref`; `\newcommand`/`\def`; `\mathscr`, `\mathbbm`, `\degree`, `\color`; `\includegraphics`; `\vspace` and friends; any non-ASCII character; any `$`.

## 5. Escaping rules (text mode)

Characters `% & # _ $ { } ~ ^ \` are special in LaTeX text. The rules tell models not to write them in text at all (put symbols in math mode, spell out words), because the escaped forms (`\%`, `\&`, `\_`) display with the backslash in the web view. Validation rejects an unescaped `& # _ ^ ~` in text mode and any `%` outside marker lines (an unescaped `%` silently comments out the rest of a line in the PDF and shows literally in the web view).

## 6. Section titles and field layout

The three parts are stored as ONE field (the app has a single `solution` column). `assemble.py` builds:

```
<solution body>            (no "Solution" title: the app already prefixes "Q<n>.")

\medskip\noindent\textbf{Rigor Notes}      (this title and block are omitted when the reviewer wrote %%% NONE)

<rigor notes>

\medskip\noindent\textbf{Takeaways}

<takeaways>
```

`\medskip\noindent` is harmless in the PDF and stripped by the web view, where the title becomes bold text on its own line. Owner may prefer a different title style; change `title()` in `assemble.py` and bump `prompt_version`.

## 7. Images

Models never include images. Question images are passed to every subagent as local file paths (copied to `outputs/<id>/images/`) and the subagent is told to open them. `check_pdf.py` compiles with the app's `\graphicspath`, so a question's own `\includegraphics` resolves exactly as in the app; `preview.pdf` includes the question text so figures show.

## 8. Answer field format

Evidence from the 3,653 filled answers overall and 959 in the target set:

- AIME: bare integers (`342`, `37`). Other sources: `\( ... \)` or `$...$` expressions sometimes ending with a period, values with units (`\(0.3 \mathrm{~kg}/\mathrm{s}\)`), multiple-choice letters (`C`, `(b)`), and `N/A` placeholders.
- Quiz auto-grading (`app/interactive/scoring.py`, `loosely_equal`): lowercases, strips whitespace and `\boxed{}`, then compares strings exactly or as floats within 0.1 percent. It only runs when `type` is `numerical`; `N/A`, `NA`, and empty answers mean "self-assess".

Rule implemented in `assemble.py` (`format_answer`):

- NUMERICAL and the value is a plain number: bare digits, e.g. `342`, `-1.5` (so the quiz float compare works).
- NUMERICAL with units or non-numeric parts, and every EXPRESSION: `\( ... \)` with the solver's delimiters, `\boxed`, and trailing period stripped; `\[ ... \]` only when the answer needs `aligned`, `cases`, or a matrix.
- NONE: the Answer field is not filled.
- Written only when the field is empty (or `N/A`) and the status is `passed` or `passed_after_escalation`.

## 9. Hint field format

Evidence: 486 filled hints (Peter Winkler, Gnadig, Levitin, Schwarz, Wilmott). Plain prose with `\( ... \)` math, one to three sentences, typically 60 to 330 characters, no title (Winkler's carry a "Title:" prefix that is an artifact of that book and is not imitated). `prompts/hint_examples.md` holds seven of them, as stored. Provisional validation bounds: 40 to 600 characters, tightened after the pilot.

## 10. Example of a correctly formatted solution body

```
The problem asks for the value of the integral. The plan is to notice that the integrand is a product of a polynomial and an exponential, which is a signal to try integration by parts.

\textbf{Step 1.} Let \(u = x\) and \(dv = e^{x}\,dx\). Then
\[
\int_0^1 x e^{x}\,dx = \left[ x e^{x} \right]_0^1 - \int_0^1 e^{x}\,dx = e - (e - 1) = 1.
\]

\begin{itemize}
\item Sanity check: the integrand is positive on \((0,1)\) and at most \(e\), so the answer must lie in \((0, e)\).
\end{itemize}

Final answer: \(1\).
```

This exact text passes `check_pdf.py` and `check_web.mjs`.
